# 大会スタッツ帳（eFootball）

eFootball の大会ごとに、チーム・対戦相手・選手のスタッツを1試合ずつ記録し、3試合以上で1試合あたりの平均値を分析する Web ツールです。
各ユーザーが自分の Google アカウントでログインし、記録はアカウントごとに保存されます（ほかのユーザーからは見えません）。

- 公開先：Vercel（静的サイト。ビルド不要）
- ログインと保存：Firebase Authentication（Google ログイン）＋ Cloud Firestore
- 外部ライブラリ：Firebase JS SDK（CDN から読み込み）のみ

## 主な機能

| モード | 記録できる内容 |
|---|---|
| チームスタッツ集計 | 勝敗・スコア（必須）、対戦相手、自チームと相手のスタッツ |
| チーム・個人簡易集計 | 上記＋ゴール・アシスト、出場GK（セーブ数・セーブ率）、イエロー・レッドカード |
| チーム・個人詳細集計 | 上記＋選手ごとの出場有無（先発・途中）、出場試合数。欠場試合を平均に含めるかを切り替え可能 |

- 記録データは1ユーザーあたり最大10件。不要なデータは［設定］から削除できます。
- 勝敗とスコア以外は空欄のまま登録でき、あとから修正・削除できます。
- パス成功率と相手の支配率（100 − 自チームの支配率）は自動で計算されます。
- 記録データごとに JSON でバックアップを書き出し・読み込みできます。

## ファイル構成

```
index.html              画面の骨組み
css/style.css           デザイン
js/app.js               アプリ本体（記録・分析・ログイン）
js/firebase-config.js   Firebase の接続設定（★ここを書き換える）
firestore.rules         Firestore のセキュリティルール（Firebase コンソールに貼り付ける）
vercel.json             Vercel の設定（セキュリティ用ヘッダーなど）
favicon.svg             アイコン
```

## 公開までの手順

### 1. Firebase プロジェクトを作る

1. https://console.firebase.google.com を開き、「プロジェクトを作成」。名前は例えば `efootball-stats`。Google アナリティクスはオフで構いません。
2. プロジェクトの概要ページで **ウェブ（`</>`）アイコン** を押してウェブアプリを追加します（Firebase Hosting の設定は不要）。
3. 表示された `firebaseConfig` の値を、`js/firebase-config.js` の該当箇所に貼り付けます。
   - この値はブラウザに公開される前提のもので、秘密情報ではありません。GitHub に置いて問題ありません。
4. 左メニュー「プロジェクトの設定」→「全般」で、**一般公開名**（Google のログイン画面に出るアプリ名。例：大会スタッツ帳）とサポートメールを設定しておくと、利用者に分かりやすくなります。

### 2. Google ログインを有効にする

1. 左メニュー「構築」→「Authentication」→「始める」。
2. 「Sign-in method」タブで **Google** を選び、有効にして保存します。

### 3. Firestore（保存先のデータベース）を作る

1. 左メニュー「構築」→「Firestore Database」→「データベースを作成」。
2. ロケーションは **asia-northeast1（東京）** を推奨。モードは「本番環境モード」を選びます。
3. 作成後、「ルール」タブを開き、このリポジトリの `firestore.rules` の内容をすべて貼り付けて **「公開」** します。
   - これで「ログインした本人だけが、自分のデータを読み書きできる」状態になります。

### 4. Vercel で公開する

1. https://vercel.com に GitHub アカウントでログインし、「Add New…」→「Project」。
2. `eFootball_status` リポジトリを「Import」。
3. 設定は次のとおり（ほぼ初期値のままで OK）：
   - Framework Preset：**Other**
   - Build Command：空欄（なし）
   - Output Directory：空欄（リポジトリ直下をそのまま公開）
4. 「Deploy」。完了すると `https://〇〇.vercel.app` の URL が発行されます。

### 5. 公開 URL をログイン許可に追加する（重要）

Firebase コンソール →「Authentication」→「設定」→「承認済みドメイン」→「ドメインを追加」で、Vercel の URL のドメイン部分（例：`efootball-status.vercel.app`）を追加します。
独自ドメインを使う場合は、そのドメインも追加してください。
※ これを忘れると、ログイン時に「このURLはログインが許可されていません」と表示されます。

### 6. 動作確認

公開 URL を開き、「Google アカウントでログイン」→ 記録データを作成 → 試合を登録 → 再読み込みしても残っていれば完了です。

## 更新のしかた

GitHub の `main` ブランチにコミットすると、Vercel が自動で再公開します。

## ローカルで確認する

ES モジュールを使っているため、ファイルを直接開くのではなく簡易サーバー経由で開きます。

```sh
npx serve .          # または  python3 -m http.server 8000
```

`localhost` は Firebase の承認済みドメインに最初から入っているので、そのままログインを試せます。
`firebase-config.js` が未設定の間は「初期設定が必要です」と表示され、見本データだけ確認できます。

## データの保存場所

```
users/{ユーザーID}/datasets/{記録データID}                  … 大会名・モード・選手リスト・通算成績
users/{ユーザーID}/datasets/{記録データID}/matches/{試合ID}  … 1試合分の記録
```

## 無料枠の目安（Firebase Spark プラン）

- Firestore：読み取り 5万回/日、書き込み 2万回/日、保存 1GiB まで無料
- 記録データを開くと、その大会の試合数ぶんの読み取りが発生します（例：30試合の大会を開く＝約30回）。
- 数十人〜100人程度の利用であれば、通常は無料枠に収まります。利用者が大きく増えた場合は Firebase コンソールの「使用量」で確認してください。

## 困ったとき

| 症状 | 対処 |
|---|---|
| 「このURLはログインが許可されていません」 | 手順5の承認済みドメインに公開URLを追加 |
| LINE や X のリンクから開くとログインできない | アプリ内ブラウザは Google ログイン非対応。「ブラウザで開く」で Safari / Chrome から開く（画面にも案内が出ます） |
| ログインのポップアップが開かない | ブラウザのポップアップブロックを解除。ブロック時は自動でページ遷移型のログインに切り替わります |
| 保存時に「ログインし直して…」と出る | `firestore.rules` が公開されているか確認 |
